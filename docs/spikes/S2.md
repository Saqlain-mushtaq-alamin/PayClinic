# S2 result: Online Mode Buyer Approval Automation

Date / who: Sun Oct 18, 2026 / Md Al Amin (Track A)

What I tried (exact commands):
Tested buyer approval automation paths in the following priority order:

1. Playwright automation against sandbox buyer portal (`https://www.sandbox.paypal.com/checkoutnow`).
2. Advanced credit card payment source (`payment_source.card` with test card numbers).
3. Manual human approval during recording sessions.
4. Deterministic simulator (`sim`).

What happened (statuses, ids, timings):

- Playwright: Works on clean sessions, but periodically encounters bot detection / challenge overlays or cookie consent screens on the sandbox domain which can cause intermittent test flakes without human intervention.
- Card (`payment_source.card`): Requires Advanced Credit/Debit Card payments to be explicitly enabled on the sandbox merchant account; fails with 422 `PAYMENT_SOURCE_CANNOT_BE_USED` if not provisioned.
- Manual approval: 100% reliable for recording fixtures and goldens.
- Simulator (`sim`): Instantaneous (0ms latency), bypasses external auth completely, perfectly reproducible.

Decision:

- For `offline` mode: `BUYER_APPROVER=sim` (default). All CI runs, developer machines, and invariant verification loops run in `offline` mode with zero flaky browser dependencies.
- For `online` mode: Default `BUYER_APPROVER=manual` for recording fixtures and live demonstrations, with optional `playwright` implementation delivered in card P2-A08 for hands-free local recordings where bot protection allows.

What this changes in the plan (if anything):
None. Confirms TECH_DESIGN §0 (T6) that `BuyerApprover` interface cleanly decouples approval mechanism from scenario logic.

# S3 result: Gemini Rate Limits and Model Selection

Date / who: Sun Oct 18, 2026 / Rifat Sarkar (Track B)

What I tried (exact commands):
Tested Gemini API models via Google AI Studio API key:
```bash
for i in {1..20}; do
  curl -s -w "\n%{http_code} %{time_total}s\n" "https://generativelanguage.googleapis.com/v1beta/models/$GEMINI_MODEL:generateContent" \
    -H "x-goog-api-key: $GEMINI_API_KEY" -H "Content-Type: application/json" \
    -d '{"contents":[{"parts":[{"text":"Reply with the JSON {\"ok\":true}"}]}],"generationConfig":{"responseMimeType":"application/json"}}'
  sleep 1
done
```
Tested against `gemini-2.5-flash` and `gemini-1.5-flash`.

What happened (statuses, ids, timings):
- 20/20 calls succeeded with HTTP 200.
- No HTTP 429 rate limits encountered at 1 RPS.
- Mean latency: 1.15s per request.
- Free tier limits on Google AI Studio:
  - 15 Requests Per Minute (RPM)
  - 1,000,000 Tokens Per Minute (TPM)
  - 1,500 Requests Per Day (RPD)
- JSON mode (`responseMimeType: "application/json"`) produced valid parseable JSON in 100% of responses.

Decision:
- Use `gemini-2.5-flash` as primary `GEMINI_MODEL` (fallback to `gemini-1.5-flash` if quotas fluctuate).
- Default `AI_PROVIDER=fixture` for all test suites and CI runs so execution is 100% deterministic, instant, and never consumes API quota.
- When generating real patches or new traces, developers set `AI_PROVIDER=gemini` and `AI_RECORD=1` to persist outputs into `fixtures/ai/`.

What this changes in the plan (if anything):
None. Confirms $0 budget requirement and provides guaranteed quota resilience for Track B.

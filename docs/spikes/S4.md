# S4 result: PayPal Agent Toolkit / MCP Evaluation

Date / who: Sun Oct 18, 2026 / Rifat Sarkar (Track B)

What I tried (exact commands):
Reviewed the PayPal Agent Toolkit documentation, MCP tool definitions, and tool execution signatures against our architecture in TECH_DESIGN §10.
Evaluated tool calls for creating and capturing orders, and inspected compatibility with our firewall interception layer.

What happened (statuses, ids, timings):
- The external PayPal Agent Toolkit requires separate external dependencies, handles network I/O internally without proxy hooks, and formats arguments differently from our frozen zod contracts (`packages/contracts/src/types.ts`).
- Intercepting external SDK network calls for the spending firewall introduces risk of untracked actions or bypassed invariant evaluation.
- Our custom `PayTools` wrapper (TECH_DESIGN §10) is ~60 lines of pure TypeScript, uses the exact zod types (`GuardRequest`, `FirewallDecision`), cleanly routes through `TraceProxy`, and runs against both the simulator and real sandbox.

Decision:
- Proceed with the architecture defined in TECH_DESIGN §0 (T8) and §10: use our internal lightweight `PayTools` interface.
- Keep the PayPal Agent Toolkit as an optional external adapter card only if time permits in Phase 3/4.

What this changes in the plan (if anything):
None. Confirms TECH_DESIGN §0 (T8). Track B proceeds directly with `PayTools` in P1-B04.
